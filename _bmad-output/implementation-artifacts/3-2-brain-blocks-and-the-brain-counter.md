# Story 3.2: Brain Blocks and the Brain Counter

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a kid,
I want to hop and bonk brain blocks to pop out brains,
so that I earn brains while I type.

## Acceptance Criteria

1. **Groups of 4 (FR32).** Targets are dealt in groups of `brain_block_every` (4): each group of slots `4k .. 4k+3` has exactly 1 brain block and 3 villager slots in a shuffled order. The shuffle uses an RNG derived from the run's injected RNG (never the global RNG, never `Array.shuffle()`), so the same seed always gives the same layout **and** the same letters as Story 3.1 did. Villager slots are still the generic `ZombieRunTarget` until Story 3.3. `tests/unit/test_zombie_run_groups.gd` checks the 1-in-4 rule over many groups and seeds.
2. **Brain block (FR33).** A brain block floats `brain_block_float_px` (48) above the ground line, with its letter tag above it. It carries the bob and down-arrow like any target when active. When its letter is typed correctly, in the same call: the level's brain total rises by `brains_per_block` (1), the zombie starts a `hop_time_s` (0.35 s) hop, the block plays its bonk and switches to its used look, and a brain pops out (self-freeing one-shot). Nothing waits on any of these.
3. **Hop never delays input.** If the next correct key arrives mid-hop, a generic key lets the hop finish. If that key's target is another brain block, a new hop restarts from the rest height. Otherwise the zombie returns to its rest height when the hop ends. The logic (index, brains, scoot) is never delayed, and there is only ever one hop tween.
4. **Brainsss (FR33, FR48).** For each brain collected, the level draws exactly one `randf()` from the run RNG. If it is below `brainsss_chance` (0.2), it requests `AudioManager.play_voice(&"vo_brainsss")`. The draw happens whether or not audio is unlocked or muted, so the RNG sequence never depends on audio state.
5. **`play_voice()` (Story 3.2 part of the audio rules).** `AudioManager.play_voice(id)` plays a voice cue on the SFX bus through the existing pool. It drops any voice line requested less than `voice_min_gap_s` (8 s, stored on `AudioLibrary`) after the last voice line that actually played. Dropped, locked or unknown calls never update the "last voice" time. `test_audio_manager.gd` covers the 8 s spacing with the fake clock.
6. **Brain counter (FR14).** Whenever the total changes, Zombie Run emits `brains_earned_changed(total)`. The shared HUD counter (already wired by `RunFrame` in Story 2.5) shows it in the same call. `get_brains_earned()` returns the same total, so the `RunResult`, the report card and Quit to Menu (FR13) all get the real count without any `RunFrame` change.
7. **Config, no literals.** `brain_block_float_px`, `hop_time_s`, `brains_per_block` and `brainsss_chance` are new `ZombieRunConfig` exports, set in `zombie_run.tres` (48, 0.35, 1, 0.2) and checked by `validate()`. `voice_min_gap_s` lives on `AudioLibrary` (8.0 in `audio_library.tres`). No GDD number appears as a literal in a script.
8. **Placeholder art and audio.** The brain block, its bonk, the brain pop and the zombie hop use code-drawn placeholders in palette colours only (pink cartoon brain like the HUD icon, 1 px ink outline, no gore). There are no new sprite sheets: final frames arrive in Story 3.6. A placeholder `vo_brainsss_01.wav` is generated by `tools/gen_placeholder_audio.gd` and credited (real lines arrive in Story 5.1).
9. **Tests.** New and updated GUT tests cover the groups, the brain block, the hop, the level's brains, signal, voice roll and determinism, `play_voice` spacing, the config and library values, and the integration result (4 keys = exactly 1 brain). The full suite passes.

### Key design decisions (follow these)

- **Three uses of randomness, kept apart.** The letters come from a child RNG seeded first (as in 3.1, unchanged). The group layout comes from a second child RNG seeded second. The Brainsss roll draws from the run RNG directly (AC: "rolled by the level with the run RNG"). With this split, a seed replays the same letters and blocks, and the voice roll can never shift the layout. The epic AC says "using the run's injected RNG" for the shuffle; a child seeded from it is how the `LevelBase` doc says a level does that.
- **Exactly one `randf()` per brain**, always, even when audio is locked, muted or throttled. The level never asks the `AudioManager` whether a voice would play. The throttle is `AudioManager`'s job alone (architecture Audio: "the 20% chance is decided by the caller, and the cooldown by AudioManager").
- **The voice gap is library-wide data.** 8 s is a GDD number, so it goes in a Resource (`AudioLibrary.voice_min_gap_s`), not a `const`. It is shared by every `vo_*` id, unlike the per-cue `min_interval_s`. Story 3.7 reads `_last_voice_msec` for its 2 s groan mute, so stamp only real plays.
- **Logic leads, visuals chase** (architecture Novel Pattern). Brains, the signal and the roll all happen synchronously in `on_char_accepted`, before any visual. The hop, bonk and pop are fire-and-forget node-bound tweens; nothing awaits them or gates on them.
- **The hop moves `Body`, never the zombie node.** The zombie node's x is the camera (`_set_zombie_x`) and its y is the ground line. A y tween on the node would fight the camera helper and the 3.4 conga line. `Body.position.y` also carries the hat slot.
- **The brain block is a `ZombieRunTarget` subclass** with the same `setup()` signature plus `configure()`. The level's queue, freeing and active logic stay untouched, and `get_queue()` still returns `Array[ZombieRunTarget]`. The architecture's example `setup(letter, slot, config)` is satisfied in spirit; changing the base signature would churn 3.1's tests for no gain.
- **GDD numbers vs look numbers.**
  - GDD numbers, config only: 48 px float, 0.35 s hop, +1 brain, 20 %, 8 s, groups of 4.
  - Derived, not retyped: the hop height `float − SIZE_PX`.
  - Look values, named `const`s in the owning script: bonk 3 px / 0.25 s, pop rise 16 px / 0.4 s, block 16×16.

### Latest tech notes (Godot 4.7.2)

- `Array.shuffle()`, `Array.pick_random()`, `randi()` and `randf()` (global) use the global RNG. Use `rng.randi_range(a, b)` (inclusive) and `rng.randf()` (in `[0, 1)`) on the injected instance.
- `Node.create_tween()` is node-bound (it pauses with the tree and dies with the node); `Tween.kill()` makes `is_valid()` false; `tween_callback(queue_free)` is the standard self-free.

- `AudioStreamWAV.save_to_wav()` is what the generator already uses; new folders need `DirAccess.make_dir_recursive_absolute(ProjectSettings.globalize_path(...))`.

### Project Context Rules

There is no `project-context.md`. The binding rules come from `_bmad-output/game-architecture.md`:
- Static typing everywhere (`untyped_declaration = Error`); `:=` only when the type is obvious.
- Typing callbacks are synchronous: no `await`, logic before visuals, one retargeting tween per moving actor (move tween, hop tween), self-freeing one-shots.
- Game numbers come only from Resources (`ZombieRunConfig`, `AudioLibrary`); no GDD literals in scripts.
- Randomness only through the injected RNG or its children; no global random functions in `scripts/levels`.
- Throttling lives only in `AudioManager`; callers decide chance, never cooldown.
- Entities: `preload`ed scene consts, `setup()`/`configure()` before `add_child`, `queue_free()` off-screen or when done.
- Signals are typed, past tense and connected in code; levels never write `PlayerData` or call the Router.
- Logging `[LEVEL][tag]` via `Log`; nothing in `_process` or on every key.
- Kid-safe art: palette only, hard pixels, 1 px ink outline, no red, the brain is a cute cartoon icon.
