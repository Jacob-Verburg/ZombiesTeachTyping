# Story 3.3: Villager Hugs and Party-Hat Zombies

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a kid,
I want my zombie to hug villagers and turn them into party-hat zombies,
so that every correct letter feels like goofy mischief.

## Acceptance Criteria

1. **Villagers replace the generic slots (FR32, FR34).** The three non-block slots in each group of 4 are now villagers. A villager stands on the path (feet on the ground line), waving (`villager_wave.png`, 2 frames at 8 fps), and carries its letter tag above its head. It gets the bob and down-arrow like any target when active. The generic `ZombieRunTarget` scene is no longer spawned by the level, but it stays as the base class and test fixture.
2. **Hug → poof → party-hat zombie (FR34).** When a villager's letter is typed correctly, in the same call:
   - the villager goes `WAITING → HUGGED`;
   - the zombie starts a `hug_time_s` (0.4 s) hug;
   - the villager runs its own fire-and-forget sequence: after `hug_time_s` it poofs (4-frame dust cloud, state `POOFED`, the villager sprite hides), and when the poof ends a party-hat zombie stands in its place.

   The state never goes backward (`WAITING → HUGGED → POOFED` only; enforced in one `_set_state()`).
3. **Hug cut, effects keep going.** If the next correct key arrives before the hug ends, the hug is cut: the zombie's hug tween is killed, `Body` returns to rest, and if that key is another villager, a new hug starts. The zombie scoots on as always. The cut never affects the villager: its poof and party-hat zombie still complete on the villager's own timer. Nothing in the typing path awaits anything.
4. **Hop and hug don't fight.** The hop (3.2) moves `Body.position.y`; the hug moves only `Body.position.x`. A villager key during a hop starts the hug, and the hop finishes (3.2 review decision: only a brain-block key restarts the hop). A brain-block key during a hug cuts the hug and starts the hop.
5. **Party-hat zombie art.** A `party_zombie_idle.png` prototype sheet (2 frames, 8 fps) is generated by `tools/gen_art_prototypes.gd`: the villager body with the skin recoloured (`s → zombie-green`, `S → zombie-green-dark`, every other legend entry kept) plus a party hat, palette-only, with the 1 px ink outline and no scary or gory details (style sheet §6, NFR10, NFR13). It passes `test_art_sprites.gd`. `scenes/characters/party_zombie.tscn` (`PartyZombie`) shows it. The poof and the hug are code-drawn or tweened placeholders. Final frames (hug 3f, poof 4f, party-hat walk 4f) arrive in Story 3.6.
6. **Config, no literals.** `hug_time_s` (0.4) is a new `ZombieRunConfig` export set in `zombie_run.tres` and checked by `validate()`. No GDD number appears as a literal in a script (the existing regex guard still passes).
7. **Nothing else changes.** Brains, the brain signal, the Brainsss roll and the layout/letters for a seed are exactly as in 3.2: villagers pay 0 brains and draw nothing from any RNG. `RunFrame`, the HUD and the run result are untouched.
8. **Tests.** New and updated GUT tests cover the villager state machine and sequence, the hug (start, cut, restart, coexisting with the hop), the level's villager wiring, the config, and the new sprite sheet. The full suite passes.

### Key design decisions (follow these)

- **The villager owns its own sequence.** HUGGED happens on the key; the poof starts `hug_time_s` later on the villager's own node-bound tween; the party zombie appears when the poof ends. The zombie's hug is a separate tween on the zombie and can be cut freely. Cutting it must never cut the villager's sequence (AC 3: "the poof and party-hat zombie still complete as fire-and-forget effects").
- **Hug on x, hop on y.** Both animate `Body` (so a future hat rides along) on different axes. No interlocks, no "which animation wins" logic, and the 3.2 review rule ("a generic key lets the hop finish") carries over to villager keys for free.
- **Logic leads, visuals chase** (architecture Novel Pattern): `resolve()` sets HUGGED synchronously and returns 0; every animation is fire-and-forget; nothing gates input on `tween.finished` or `Poof.finished`. `Poof.finished` → show party zombie is an effect chain, not input gating, so it is allowed.
- **No randomness in villagers.** The 3.2 review flagged that the run RNG has a single consumer (the Brainsss roll). Any new draw would shift replays. Villagers need none; if a later story wants random villager looks, give it a new child RNG seeded **after** the existing two.
- **`poofed(party_zombie)` is the hand-off for 3.4.** Story 3.4 must count conga members **logically at resolve time** (a villager resolved = +1), not on `poofed`, because at very high speed a villager can scroll off and be freed before its poof ends (0.4 s + 0.33 s vs ~1 s to scroll off at 5 keys/s). Write this in the villager header and in deferred-work.
- **The party zombie art comes from the existing tool.** `gen_art_prototypes.gd` was built for this (its header and `VILLAGER_LEGEND` comment name Story 3.3): a recolour is a legend change. This keeps the party zombie palette-correct and test-covered, and 3.6 only adds the walk frames.
- **GDD numbers vs look numbers.**
  - GDD numbers, config only: `hug_time_s` 0.4.
  - Art-spec and look values, named consts in the owning script: poof 4 frames at 12 fps, hug lean 3 px, wave 8 fps (in the `.tscn`).
  - The regex guard bans `120 | 0.15 | 26 | 0.35 | 48 | 0.2` in `scripts/levels/zombie_run/*.gd`. Don't write any of those (e.g. no `0.2` for the poof timing; `4.0 / 12.0` is fine).

### Latest tech notes (Godot 4.7.2)

- `Tween.tween_interval(t)` followed by `tween_callback(f)` is the idiomatic delayed call on a node-bound tween (it pauses with the tree; `SceneTree.create_timer` would not be node-bound by default; don't use it).

### Project Context Rules

There is no `project-context.md`. The binding rules come from `_bmad-output/game-architecture.md` and `docs/art-style-sheet.md`:
- Static typing everywhere; `:=` only when the type is obvious.
- Typing callbacks are synchronous: no `await`, logic before visuals, one tween per moving actor per axis (move, hop, hug), self-freeing one-shots.
- Entity visual states use an enum + `_set_state()` and never go backward (architecture State Patterns: "a villager: `WAITING → HUGGED → POOFED`").
- Game numbers come only from `ZombieRunConfig`; no GDD literals.
- Randomness only through injected RNGs; villagers use none.
- `preload`ed scene consts, `setup()`/`configure()` before `add_child`, `queue_free()` when done or off-screen.
- Signals are typed, past tense and connected in code; node refs via `%Unique` / `@onready`.
- Logging via `Log`, never in `_process` or per key.
- Art: palette only, hard pixels, 1 px ink outline, 2–6 frames at 8–12 fps, the party-hat zombie is a villager recolour plus a hat, kid-safe (NFR10).
