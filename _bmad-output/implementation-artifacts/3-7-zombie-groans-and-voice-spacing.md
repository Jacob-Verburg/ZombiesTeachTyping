# Story 3.7: Zombie Groans and Voice Spacing

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a kid,
I want my zombie to groan now and then, but not constantly,
so that it sounds funny without getting annoying.

## Acceptance Criteria

1. **Ambience API (FR48).** `AudioManager.start_ambience()` and `AudioManager.stop_ambience()` exist (architecture Audio API). While ambience is on, one groan, picked at random from 4, plays every 3–8 s. Each gap is a fresh random interval in `[groan_min_interval_s, groan_max_interval_s]` (3.0 and 8.0). Groans are never tied to keypresses: no `play_sfx`/`play_voice` call or typed key changes when the next groan is due.
2. **Groan mute after a voice line (FR48).** When a groan comes due less than `groan_voice_mute_s` (2.0 s) after the last voice line that actually played (`_last_voice_msec`, Story 3.2), that groan is skipped and the next one is scheduled as normal. A groan never stamps the voice time, so a groan never blocks a "Brainsss".
3. **Only while `RUNNING`.** `RunFrame` turns ambience on when the run enters `RUNNING` (first correct key, and again after a resume countdown back into `RUNNING`). It turns it off whenever the run leaves `RUNNING` (pause, ending through timer, F6 or `end_requested`) and when the frame leaves the tree. No groans play while waiting for the first key, paused, counting down, ending (the dance) or done.
4. **Audio rules still hold.** Groans play on the SFX bus through the existing 8-player pool (the Sound toggle mutes them, FR46). Nothing plays before `unlock()` (FR47); a locked tick only reschedules. Groan selection uses `AudioManager`'s own RNG, never the run RNG (seed replays stay identical) and never the global RNG. With 2+ groan ids, the same groan never plays twice in a row.
5. **Config, no literals.** The 4 groan ids, the 3 s / 8 s interval and the 2 s mute live on `AudioLibrary` (`data/audio/audio_library.tres`), not as literals in scripts. A broken setup (no groan ids, min ≤ 0, max < min) logs once at `start_ambience()` and plays nothing, and never a groan every frame.
6. **Placeholder groans.** Four placeholder groans (`sfx_groan_01` … `sfx_groan_04`) are generated by `tools/gen_placeholder_audio.gd` (deterministic, the 4 existing files stay byte-identical), added to the library and credited in `assets/audio/CREDITS.md`. The real groans arrive in Story 5.1.
7. **Tests (fake clock).** `test_audio_manager.gd` proves the 3–8 s interval, the 2 s mute after a voice line, stop/start, the lock gate, the bus, and the no-repeat pick with the fake clock and a seeded RNG. `test_run_frame.gd` proves the start/stop calls for every state change. The throttle and voice tests from Stories 2.5 and 3.2 keep passing unchanged. The full suite passes.

## Dev Notes

### What this story is (and isn't)

- It adds the last audio rule from FR48: random groans every 3–8 s during a run, skipped within 2 s of a voice line. That's the `AudioManager` ambience API plus `RunFrame` turning it on and off. **Gameplay does not change.**
- **New files:** 4 placeholder groan WAVs (+ `.import`) in `assets/audio/sfx/`.
- **Updated files:** `scripts/autoloads/audio_manager.gd`, `scripts/resources/audio_library.gd`, `data/audio/audio_library.tres`, `tools/gen_placeholder_audio.gd`, `assets/audio/CREDITS.md`, `scripts/run/run_frame.gd`, `scripts/levels/zombie_run/zombie_run_level.gd` (header line only), `tests/unit/test_audio_manager.gd`, `tests/unit/test_audio_library.gd`, `tests/integration/test_run_frame.gd`, `deferred-work.md`, `sprint-status.yaml`.
- **Don't build:** real groan/voice recordings, a second Brainsss line, bonk/hug-poof SFX, the Zombie Run music loop, music crossfade or paused-music ducking (all 5.1); a per-level ambience flag; groans in menus; any change to `TypingSession`, `TypingInput`, `LevelBase`, `PlayerData`, `RunResult`, the HUD, `Router` or the save.

### Key design decisions (follow these)

- **Timing lives in `AudioManager`, on/off lives in `RunFrame`.** The architecture puts every throttle rule in `AudioManager` ("one place for audio rules", D7) and the run lifecycle in `RunFrame` (ADR-1). A level never owns run state, so it never calls start/stop.
- **Polling against `now_msec`, not a `Timer` node.** The existing throttle and voice gap already read the injectable `now_msec` clock; using it for the groan schedule keeps one clock and lets tests drive everything with `_now` plus `_update_ambience()`. A `Timer` would need real seconds in GUT.
- **Stop on pause explicitly.** `AudioManager` is `PROCESS_MODE_ALWAYS` (Router fades pause the tree, and music must go on), so a tree pause does **not** freeze the groan schedule. `RunFrame` must call stop on leaving `RUNNING`. Restart after the countdown draws a fresh 3–8 s gap, so a groan never lands right on "GO".
- **Reschedule on every due tick, played or not.** A skipped groan (locked, muted by a voice, unknown id) must still move `_next_groan_msec`, or `_update_ambience` would retry every frame and fire the moment the 2 s mute ends (that would be "tied to the voice line", and a log storm on an unknown id).
- **A groan is not a voice line.** It doesn't stamp `_last_voice_msec` and isn't protected from SFX stealing like `_voice_player`. FR48's mute is one-directional: groans yield to voice, never the other way.
- **Own RNG.** The run RNG has an exact draw budget (letters child, layout child, one Brainsss roll per brain: see the `zombie_run_level.gd` header). Audio must never draw from it, or seeds would replay differently. The global RNG is off limits too (`pick_random`/`shuffle` would break the "no global RNG" rule and make tests flaky).
- **No repeat.** With 4 groans, a back-to-back repeat sounds like a stuck sample; excluding the last id is cheap and fits the story's "not annoying" goal.
- **Ids `sfx_groan_0N` in `assets/audio/sfx/`.** The library's id prefixes are `sfx_*`, `mus_*`, `vo_*`, and `vo_*` means "goes through `play_voice` and its 8 s gap", which groans must not. The architecture folder list puts non-voice-line effects in `sfx/`.

A synchronous test body never lets a frame pass, so move `_now`, call `_update_ambience()` and assert on its return value in the same body. **Don't `await` in ambience tests**: a frame in between would let the engine's `_process` consume the due groan first, and the test's call would then see null.
- `assert_push_warning("…")` matches the `Log.warn` text; keep the warning strings stable.
- Keep every touched text file LF (`.gitattributes` `eol=lf`; Windows CRLF trap from 2.10).
- `assert` in headless GUT logs a `SCRIPT ERROR` and doesn't abort: use `Log` plus safe returns on paths tests reach.

### Implementation Plan

- Timing lives in `AudioManager`, which polls the injectable `now_msec` clock in `_process` (no `Timer` node). `_update_ambience()` returns early when ambience is off or the groan is not due yet (two comparisons). A due tick reschedules first, then drops the groan if audio is locked, or skips it if a voice line played less than `groan_voice_mute_s` ago. Otherwise it picks and plays one.
- Picks come from `ambience_rng`, filtered to exclude `_last_groan_id`. No `pick_random`/`shuffle` and no run RNG.
- `RunFrame._set_state()` is the single place ambience switches: off when leaving `RUNNING`, on when entering it. `_exit_tree()` turns it off if the frame is freed while `RUNNING`.
