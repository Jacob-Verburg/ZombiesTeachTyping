# Story 1.4: Audio Manager and Browser Audio Unlock

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a kid,
I want sound to start as soon as I click or press a key on the title screen,
so that the game is not silent on the web and never blasts sound before I interact.

## Acceptance Criteria

1. **Bus layout.** Given the audio bus layout, when it is inspected, then `Master` has `Music` and `SFX` children with no bus effects.
2. **Pool, library, lock.** Given `AudioManager` with a pool of 8 SFX players and one music player, and `data/audio/audio_library.tres` mapping sound ids to streams and volumes, when `play_sfx(id)` is called before `unlock()`, then nothing plays (FR47); and an unknown sound id logs a warning and does not crash.
3. **Unlock on the title.** Given the title screen, when the first key or click happens, then `AudioManager.unlock()` is called from that input callback, and a placeholder UI click and a placeholder menu music loop start playing on the web build.
4. **Bus mute.** Given `AudioManager` bus mute methods, when the Music or SFX bus is muted, then only that bus goes silent.

### Web audio facts (Godot 4.7)

- Since 4.3, web audio uses the **Web Audio API "Sample" playback** by default (`audio/general/default_playback_type.web`). This works without threads (our Web preset has Thread Support off). Its limits are no `AudioEffect`s, no reverb and no procedural audio. Per-bus **volume and mute work**. That's why the architecture says "no bus effects" (D7). Don't switch players to `Stream` playback.
- Browsers keep the `AudioContext` suspended until a user gesture. Godot resumes it on user interaction. The "AudioContext was not allowed to start" console warning before the first input is **expected** (1.2 and 1.3 notes).
- `unlock()` is the **game-level** gate that guarantees FR47 on every platform, including desktop, where no browser would block anything. It doesn't call any browser API itself.
- Known trap: playback requested before the context resumes can be lost or start silently on web. The pending-music design avoids this, because music is only started from `unlock()`, which runs inside the gesture.
- `AudioStreamPlayer` follows `process_mode`: it pauses while the tree is paused unless it can process (see 4.3).

### Architecture compliance

- **D7 / Audio Architecture:** `Master → Music / SFX`, no bus effects, a pool of 8 SFX players plus one music player, throttling only in `AudioManager`, `unlock()` called from the title input callback, OGG music and 16-bit WAV SFX.
- **D5 / Static data:** `AudioLibrary` is a typed Resource in `scripts/resources/`; its instance is in `data/audio/`. Boundary 5: `.tres` files only reference classes from `scripts/resources/`. `AudioCue` lives there too.
- **Boundary 3:** only `AudioManager` creates audio players. Only `WebPlatform` touches browser APIs, so there's no `JavaScriptBridge` here.
- **Autoload rules:** no `class_name` on the autoload; `AudioManager` (4th) may only use `WebPlatform`, `SaveService` and `PlayerData` in `_ready()`, and it needs none of them.
- **Error handling:** a missing sound never stops anything (NFR16). It gets `Log.warn` and is skipped; no `assert`. A missing bus is `Log.error` plus return.
- **Logging:** tag `&"audio"`. `info` once on unlock; `warn` for unknown ids; `debug` for anything chatty. Never log in `_process` (there is none).
- **Naming:** sound ids `sfx_*`, `mus_*` and `vo_*`; files `sfx_<event>.wav` and `mus_<context>.ogg`; tabs; strict typing everywhere (`untyped_declaration = Error`).
- **Config:** GDD numbers (throttle ms, voice spacing) will live in a config resource or constants **when** 2.5 and 3.2 add them. This story adds no gameplay numbers.

- Godot web export docs (4.4/4.5, which still apply to 4.7): audio uses the Web Audio API since 4.3. "Sample" playback is the default on web and gives low latency without threads. It doesn't support `AudioEffect`s, reverb, doppler or procedural audio. The `Stream` mode is opt-in per player or through `audio/general/default_playback_type.web`.
- Silence on the first web load usually comes from playback requested before the gesture resumes the context, or from the first scene starting music with no unlock gate. Our pending-music gate covers both.
- `AudioStreamPlayer`: playback pauses with the node's `process_mode` (`stream_paused` follows the tree pause). Use `PROCESS_MODE_ALWAYS` for audio that must survive `get_tree().paused`.
- `AudioStreamWAV.save_to_wav(path)` writes a WAV from in-memory PCM; WAV loop options are import options (`edit/loop_mode`, `edit/loop_begin`, `edit/loop_end`).
- There's no OGG encoder on this machine (no ffmpeg, oggenc or sox) and Godot can't encode Vorbis. So the placeholder music is a looping **WAV** (see Variance). Story 5.1 brings the real OGG loops.

### Project Structure Notes

- Matches the architecture: `scripts/autoloads/audio_manager.gd`, `scripts/resources/audio_library.gd`, `data/audio/audio_library.tres`, `assets/audio/{music,sfx}/` and `tests/unit/test_audio_manager.gd` (2.5 and 3.7 extend this file).
